# 📋 Полипак // Чек-листы производства (Frontend)

Веб-приложение для автоматизации ежесменных осмотров оборудования, приёмки/сдачи смен,
фиксации дефектов и ролевого утверждения протоколов на производственных линиях **ООО «Полипак»**.

Интегрировано с бэкендом [ChecklistsAPI](https://github.com/LLC-Polipak/ChecklistsAPI) (Django REST Framework).

---

## 🚀 Основной функционал

### 1. Конструктор шаблонов чек-листов (Template Builder)
* Создание и редактирование чек-листов под станки цеха (экструдеры, пакетоделательные линии, флексопечать).
* Разбивка вопросов на разделы и пошаговые экраны (Stepper).
* Поддержка типов полей: `RADIO` (ДА/НЕТ), `INTEGER` (числа), `CHOICE` (выбор из списка), `CHECKBOX`, `STRING`, `DATE`, `AUTO_DATE`.
* **Rule Engine**: допустимые границы технологических параметров (min / max для температур и давлений) и подсветка брака.
* Клонирование шаблонов на другие станки.

### 2. Заполнение чек-листа (Checklist Runner)
* Пошаговый визард заполнения с валидацией обязательных полей.
* Автоматическая фиксация дефекта при выходе параметров за пределы нормы.
* Требование обязательного комментария и прикрепления фото при обнаружении неисправности.
* Сохранение промежуточных черновиков.

### 3. Журнал смен (Results Journal)
* Таблица проверок с перетаскиванием колонок и сортировкой.
* Фильтры: по станку, дате смены, быстрые переключатели *«Только с дефектами»* и *«Только черновики»*.
* Просмотр истории изменений анкеты.

### 4. Электронные подписи и утверждение смены
* **1. Сдал смену**: фиксируется оператором при отправке чек-листа.
* **2. Принял смену**: фиксируется сменщиком при приеме станка.
* **3. Утвердил**: ставится мастером цеха или главным механиком. Только после подписи мастера смена окончательно закрывается и блокируется зеленым замком от любых правок.

### 5. Аналитический дашборд (Analytics Dashboard)
* Расчёт показателей: исправность парка оборудования (%), процент выполнения плана обходов, число дефектов.
* Графики: динамика инцидентов во времени, ТОП-5 проблемных станков цеха, дефекты по узлам оборудования.
* Оперативный журнал последних зафиксированных аварий (Live Feed).

## ⚙️ Установка и запуск (Linux / Windows / macOS)

### 1. Клонирование репозитория
```bash
git clone git@github.com:Gorge228/ChecklistsFrontend.git
cd ChecklistsFrontend

### 2. Установка зависимостей
Выполняется строго в корне проекта (где находится package.json):
npm install

### 3. Настройка адреса бэкенда

Файл настроек: src/config/api.config.ts.
Если сервер Django запущен на стандартном адресе, менять ничего не нужно:

export const APP_CONFIG = {
    // Адрес бэкенда Django
    BACKEND_URL: 'http://127.0.0.1:8000',

    // Префикс API
    API_BASE_URL: '/api/v1',

    // Таймаут запросов
    TIMEOUT_MS: 15000,
};

### 4. Запуск приложения
Вариант А: Запуск С РЕАЛЬНЫМ БЭКЕНДОМ DJANGO
npm run dev

Вариант Б: Запуск БЕЗ БЭКЕНДА (Автономный демо-режим)
(Django не нужен. Все данные, таблицы и подписи работают локально в памяти):
npm run dev:mock
